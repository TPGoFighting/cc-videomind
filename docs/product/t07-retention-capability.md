# T07 站内留存系统能力合同

状态：核心代码已实现，待首页/导航隔离集成、双视口浏览器和生产 PostgreSQL 验收
依据：D4 已确认首发只做站内“今日复习”；邮件提醒需要验证邮箱、同意和退订能力后另立任务。

## CAPABILITY

登录用户保存一个单词或句子后，该学习项会在约 24 小时后进入可解释的站内复习队列。用户能看到项目为何在今天出现、下一次复习时间、来源视频和时间点；完成一组复习后能继续回到来源学习。设置页允许调整后续复习节奏，系统仅在具有完整七天窗口和足够学习行为时生成个人周回顾，否则明确显示“继续学习以生成周报”。

## CONSTRAINTS

### 固定产品规则

- 单词和句子都是学习收藏，必须进入同一“今日复习”体验，不能让句子停留在只读收藏页。
- 首次复习固定在保存约 24 小时后，不因频率设置而延后到两天以上。
- 频率设置只调整首次复习之后的 SM-2 间隔与每日呈现上限。
- 每个队列项必须包含到期原因、计划时间和来源视频；有可信时间点时生成来源跳转，没有时间点的历史单词只跳到视频开头并明确降级。
- 答错项目 10 分钟后再次出现；答对项目按 SM-2 和用户频率计算下一次复习。
- 周回顾只使用站内权威数据，不调用 AI，也不读取字幕、句子正文或笔记正文生成统计。
- 产品分析仍遵循 T06 的主动同意与白名单事件规则；关闭分析不能阻止个人复习功能。

### 数据与信任边界

- 腾讯 PostgreSQL 是生产权威；本地 SQLite 只用于开发和无生产数据的验收。
- 客户端不得提供或覆盖 `user_id`；所有个人队列、偏好和周回顾查询按已认证会话过滤。
- 来源 `video_id` 和时间点来自保存动作及服务端存储；回跳链接必须验证视频 ID 并限制时间为非负整数。
- 复习提交必须校验项目归属，不能仅凭 lemma 或 quote ID 更新其他用户的状态。
- 首页、导航和复习页只读取聚合的“今日待复习数量”，不暴露收藏正文。

### 失败与恢复

- 队列加载失败时保留页面和重试入口，不把失败误显示为“今天没有任务”。
- 单题提交失败时不应静默推进为已完成；需要显示未同步状态并允许重试。
- 历史单词缺少时间点时保留复习资格，不伪造来源秒数。
- 周回顾数据不完整时返回结构化 `collecting` 状态，不生成猜测性总结。

## IMPLEMENTATION CONTRACT

### Actors

- 学习用户：保存、查看今日队列、完成复习、调整频率、查看周回顾。
- 站内页面：展示待复习数量和明确收益，不发送站外提醒。
- 运营管理员：只通过 T06 聚合指标查看 D1/D7，不读取个人学习正文。

### Surfaces

- 视频学习工作台：保存单词时同时保存当前字幕时间点；单词和句子均显示“约 24 小时后复习”。
- `/review`：统一呈现单词与句子、到期原因、来源回跳、完成进展和下一步。
- `/settings`：复习节奏选择，说明首次复习不变、后续间隔和每日上限的差异。
- 首页/导航：显示今日待复习数量和“回到语境巩固记忆”的收益。
- 站内周回顾：显示七天完成量、活跃天数、保存量和待复习量；数据不足时显示收集进度。

### States and transitions

```text
saved -> scheduled_first_review -> due -> reviewing
reviewing + quality < 3 -> retry_in_10_minutes
reviewing + quality >= 3 -> scheduled_by_sm2
scheduled_by_sm2 -> due
deleted_source -> review_state_deleted
```

周回顾状态：

```text
collecting -> ready
```

`ready` 必须同时满足：账户覆盖完整七天窗口、至少两个活跃复习日、至少三次已完成复习。否则保持 `collecting` 并返回缺失条件。

### Interfaces and outputs

- 今日摘要：`dueCount`、`wordCount`、`quoteCount`、`nextReviewAt`、`dailyLimit`、`cadence`。
- 队列项：`kind`、稳定 ID、显示内容、复习状态、`dueReason`、`nextReviewAt`、`source`。
- 来源：`videoId`、可选 `startTime`、经过验证的站内 `href`。
- 复习提交：项目 kind/ID、0–5 quality；返回已完成数量和每项新的可解释计划。
- 周回顾：`status`、窗口、完整性条件、完成数、活跃天数、保存数和下一步文案。

## NON-GOALS

- 不发送邮件、推送、短信或日历邀请。
- 不建立通知权限、验证邮箱、退订列表或营销自动化。
- 不用 AI 生成周报文字，不把个人学习正文写入产品事件。
- 不承诺跨设备实时推送；登录后的 PostgreSQL 状态是唯一同步来源。
- 不在本地实现完成后自动迁移或修改生产数据库。

## OPEN QUESTIONS

- 首页和导航当前存在未提交的 Taste 设计实验。留存组件可先独立实现并验收，最终嵌入需要在不混入用户改动的独立提交中完成。
- 历史单词没有来源时间点；本轮采用可解释降级，不做不可靠的字幕反查。
- 更长期是否支持用户关闭某个收藏项的复习，需要真实用户反馈后再决定；首发只支持删除收藏或调整整体节奏。
