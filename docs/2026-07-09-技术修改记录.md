## 1. 问题诊断：AI 功能返回空结果

### 1.1 问题描述

Word Definitions、Moments、Summary 等 AI 功能返回空结果或报错。

### 1.2 根因分析

LongCat API 返回 `thinking` 内容块（推理过程），而不是标准的 `text` 内容块：

```json
{
  "content": [
    {"type": "thinking", "thinking": "让我分析这个请求..."},
    // 注意：没有 type: "text" 块！
  ]
}
```

原代码只查找 `text` 块，找不到时返回 `null`，导致 JSON 解析失败。

### 1.3 解决方案

**文件**：`lib/ai/provider.ts`

```typescript
// 原代码：只查找 text 块
const textBlock = content.find(b => b.type === "text");
if (textBlock?.text) return textBlock.text;

// 新代码：回退到 thinking 块
const thinkingBlocks = content.filter(b => b.type === "thinking");
if (thinkingBlocks.length > 0) {
  return thinkingBlocks.map(b => b.thinking).join("\n");
}
```

## 2. 问题诊断：JSON 提取失败

### 2.1 问题描述

Thinking 内容中嵌入了 JSON，但 `parseJsonContent()` 无法提取。

### 2.2 根因分析

Thinking 文本结构：

```
1. 分析请求...
2. 生成响应...
{"definitions": [{"lemma": "hello", ...}]}
```

原 `extractBalancedJson()` 只能找到第一个 `{`，可能匹配到推理过程中的 JSON 片段。

### 2.3 解决方案

**文件**：`lib/utils/json.ts`

新增 `extractJsonFromThinking()` 函数，实现 3 种提取策略：

```typescript
export function extractJsonFromThinking(text: string): string | null {
  // 策略1：从最后一个 ```json 代码块提取
  // 策略2：通过键名模式查找 ("definitions":, "moments": 等)
  // 策略3：从后向前提取最后一个完整 JSON 对象
}
```

**文件**：`lib/ai/provider.ts`

更新 `parseJsonContent()` 使用新函数：

```typescript
// 从 thinking 文本中智能提取 JSON
const thinkingJson = extractJsonFromThinking(content);
if (thinkingJson) {
  return JSON.parse(thinkingJson);
}
```

## 3. 问题诊断：请求体过大

### 3.1 问题描述

解析视频 `2zdL__16MY4` 时报错 "Request body is too large"。

### 3.2 根因分析

**文件**：`lib/utils/api.ts`

```typescript
// 原代码：硬编码 128KB 限制
if (contentLength > 128_000) {
  return errorResponse("payload_too_large", "Request body is too large.", 413);
}
```

该视频字幕有 1672 段，请求体 185KB，超过 128KB 限制。

### 3.3 解决方案

**文件**：`lib/utils/api.ts`

移除硬编码限制，让各路由的 `withSecurity` 中间件自行控制：

```typescript
export async function readJson<T>(request: Request, schema: ZodSchema<T>) {
  try {
    const body = (await request.json()) as unknown;
    return { ok: true as const, data: schema.parse(body) };
  } catch (error) {
    // ...
  }
}
```

**文件**：`app/api/analyze/route.ts`

增加 analyze 端点的 body size limit：

```typescript
// 原：maxBodySize: 512 * 1024,
// 新：
maxBodySize: 1024 * 1024,  // 1MB
```

## 6. 技术决策记录

### 6.1 为什么移除硬编码的 body size limit？

- 各路由的 `withSecurity` 中间件已有独立的 `maxBodySize` 配置
- 硬编码限制与中间件限制重复，且过于保守（128KB）
- 长视频字幕可能超过 128KB，需要更灵活的限制

### 6.2 为什么使用 thinking 块回退而不是禁用 thinking？

- LongCat API 的 thinking 行为是模型特性，无法通过参数禁用
- Thinking 内容包含推理过程，有时包含有用的上下文
- 回退方案更健壮，兼容未来的模型更新

### 6.3 为什么 JSON 提取需要 3 种策略？

- 不同模型/请求的 thinking 格式不同
- 有些返回代码块，有些直接内嵌 JSON
- 多策略确保各种情况都能正确提取
