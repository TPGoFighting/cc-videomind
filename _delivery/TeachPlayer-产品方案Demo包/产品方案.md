## 2. 需求来源

**2.1 痛点**
- YouTube 是优质学习内容的最大入口，但「观看 ≠ 吸收」：字幕分散、重点难定位、生词需跳转词典、笔记散落各处。
- 现有字幕/翻译工具只解决「看得见」，不解决「学得会」——缺少基于上下文的理解、缺乏记忆闭环。
- 通用 AI 对话工具（如 ChatGPT）无法感知「你正在看的那条具体视频」，回答容易脱离上下文、无法引用时间戳。

**2.2 需求来源**
- 个人学习刚需：作者本人用 YouTube 学英语与技术的过程中，反复遇到「来回切窗口查词、记不住、找不到重点」的低效循环。
- 用户验证：首页 / 历史 / 单词本 / 复习等模块上线后，真实解析记录与复习打卡数据验证了「字幕→生词→复习」这条链路确有留存价值。

**2.3 解决的问题**
把「看视频」升级为「学视频」——用 AI 完成信息提取与答疑，用间隔复习完成长期记忆，用统一工作区完成知识沉淀。

## 3. 产品方案设计

**3.1 产品定位**
> 一个「以视频为单位的 AI 学习工作区」，不是播放器，也不是词典，而是连接「内容输入 → AI 加工 → 个人知识库 → 长期记忆」的闭环工具。

**3.2 核心功能**

| 模块 | 功能 | 说明 |
|------|------|------|
| 视频解析 | 一键解析 | 粘贴 YouTube 链接，自动拉取元数据 + 字幕（4 层回退链保障覆盖率） |
| AI 加工 | 智能摘要 | 大模型生成结构化摘要 + 分段要点 |
| AI 加工 | 关键时刻 | AI 提取最有价值的学习片段，双语展示，点击跳转播放 |
| AI 加工 | AI 对话 | 基于视频字幕上下文答疑，回答带时间戳引用 |
| 学习 | 单词/句子收藏 | 点击字幕中的单词/句子，一键收藏到生词本 / 语料库 |
| 学习 | 个人笔记 | 每条视频独立 Markdown 笔记 |
| 记忆 | 间隔复习 | SM-2 算法驱动，答题式闪卡 + 每日打卡 + 日历热力图 |
| 系统 | 深色模式 / 响应式 | 全站深色主题，桌面与移动端自适应 |

**3.3 核心交互流程**
1. 首页粘贴 YouTube 链接 → 解析 videoId → 进入视频工作区。
2. 工作区左侧播放视频，右侧 Tab 切换：转录文本 / Chat / 笔记 / 复习。
3. 转录文本支持原文 / 译文 / 双语切换，自动跟随播放滚动，单词可 hover 查词并收藏。
4. AI 按需生成摘要 / 关键时刻 / 对话；结果缓存 7 天。
5. 收藏的单词、句子、笔记进入个人库；每日进入复习页用 SM-2 算法巩固记忆。

**3.4 信息架构（页面路由）**
`/` 首页 · `/video/[id]` 工作区 · `/history` 历史 · `/vocabulary` 单词本 · `/quotes` 句子本 · `/notes` 笔记本 · `/review` 每日复习 · `/settings` 设置 · `/login`、`/register` 登录注册。

## 4. AI 工作流程

**输入**：用户粘贴的 YouTube 链接（视频 URL）；以及在工作区内的追问问题（Chat）、需要翻译的字幕段落。

**处理链路**：

```
用户链接
  │
  ├─[1] 解析层：提取 videoId → 拉取元数据 + 字幕（Innertube → HTML → npm 包 → Supadata 4 层回退）
  │
  ├─[2] AI 摘要层：字幕切片 → 大模型生成结构化摘要 + 分段要点（Zod 校验 + 失败修复）
  │
  ├─[3] AI 关键点层：模型挑出最有价值的片段，输出带时间戳的双语要点
  │
  ├─[4] AI 对话层：用户提问 + 视频字幕上下文 → 模型生成带时间戳引用的回答
  │
  └─[5] 缓存层：结果写入 video_analyses（7 天缓存），避免重复消耗
```

**AI Provider 设计**：统一的 `AiProvider` 接口（`OpenAiCompatibleProvider` / `GeminiProvider`），内置模型回退链（deepseek-v4-flash → qwen → glm → kimi），AI 配置优先级：用户个人设置 > 全局设置 > 环境变量。所有 AI 输出经 Zod Schema 校验，失败时触发 `repairAnalysis` 等修复逻辑。

**最终输出**：结构化摘要、带时间戳的关键时刻、基于上下文的对话回答、单词/句子的翻译与释义。

**需要用户确认的环节**：
- 字幕翻译语言模式（原文 / 译文 / 双语）由用户手动切换确认；
- 收藏单词 / 句子、保存笔记需用户主动点击确认；
- 复习答题时的评分（忘了 / 模糊 / 记得 / 简单）由用户选择，影响 SM-2 间隔；
- AI 生成内容默认仅供参考，用户可重新生成或继续追问。

## 6. 预期收益

**用户价值**
- 学习效率：把「找重点 + 查词 + 记笔记」三步合并到同一工作区，单次学习的信息提炼时间预计缩短 50%+。
- 记忆留存：SM-2 间隔复习把「看过即忘」转为「可量化掌握」，单词/知识点长期留存率显著提升。
- 体验改善：深色护眼、自动跟随滚动、hover 即时查词，降低学习摩擦。

**效率提升（产品侧）**
- 字幕 4 层回退链保障解析成功率；AI 结果 7 天缓存减少重复推理成本。
- 统一 `AiProvider` 接口 + 模型回退链，提升 AI 可用性与成本韧性。

**商业价值**
- 免费增值（Free + 订阅）模型：Stripe 结账 + Webhook 已接入，可按解析额度 / 高级模型 / 复习容量分层变现。
- 安卓 APP 已出 Beta，具备移动端获客与留存基础，可进一步做内容社区 / 学习数据报告等延伸。

## 7. 项目复盘

**收获**
- 完整跑通了「字幕提取 → AI 加工 → 个人知识库 → 间隔复习」的端到端闭环，验证了产品假设。
- 沉淀出可替换的 Provider 架构（AI / 字幕均可热切换）与统一的 API 安全包装（`withSecurity`：CSRF + 限速 + 体积限制），工程可维护性高。
- 深度实践 RLS 行级安全、Zod 输入/输出校验、AI 输出修复等关键工程实践。

**遇到的问题**
- YouTube 字幕获取不稳定（地域 / 反爬），需用 4 层回退链 + 外部 API 兜底。
- AI 输出偶发格式错误，需 Zod 校验 + 修复逻辑兜底，保证前端不崩。
- 移动端交互（hover 查词、Tab 切换）需单独适配，开发量高于预期。

**当前不足**
- 摘要 / 关键时刻为一次性生成，缺少「多轮迭代 + 用户微调」能力。
- 复习题型较单一（选择释义 / 选择单词），缺少拼写、听写等主动回忆题型。
- 缺少学习成效量化报告（如掌握曲线、预测遗忘点）来增强留存动机。

**下一步迭代计划**
1. 增加「关键时间点」可视化时间轴 + 用户手动标记重点。
2. 复习题型扩展：拼写、听写、句子补全；引入「预测遗忘」提醒。
3. 学习数据报告：掌握曲线、周报、连续学习激励。
4. 安卓 APP 正式版 + 桌面端（已含 Tauri 工程），打通多端同步。
5. 探索内容社区 / 共享笔记，提升网络效应与付费转化。
