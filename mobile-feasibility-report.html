3 各方案详细分析

3.1 PWA（渐进式 Web 应用）

PWA 不需要额外代码库，仅需为现有 Next.js 应用添加 manifest.json 和 Service Worker。 用户可通过浏览器"添加到主屏幕"，获得接近原生应用的启动体验。

优势：

  • 零额外代码库，100% 复用现有逻辑和 UI
  • 自动同步 Web 版本更新，无需审核流程
  • 支持离线缓存（字幕、分析结果等）
  • 开发时间：1-2 天

局限：

  • 无法上架 App Store / Google Play
  • iOS 限制较多（后台播放、通知受限）
  • 用户认知度低，很多人不知道"添加到主屏幕"功能
  • 无法使用原生 API（蓝牙、HealthKit 等，但本项目不需要）

PWA 实施要点

只需新建 manifest.json + sw.js（或使用 next-pwa 插件），配置图标、启动画面、离线策略。现有响应式布局已适配移动端，无需额外 UI 改动。

3.2 React Native + Expo

使用 React Native 重写 UI 层，保留现有的 Supabase SDK、Zod schema、AI Provider 接口等纯逻辑代码。 Expo 提供统一的开发工具链和构建服务。

优势：

  • React 生态，学习成本低
  • 可复用 Zod schema、类型定义、AI Provider、部分 Supabase 逻辑
  • Expo 简化构建、OTA 更新、EAS 提交
  • 原生视频播放器、手势、动画体验好

挑战：

  • UI 层需完全重写（Tailwind → NativeWind 或 StyleSheet）
  • shadcn/ui 不可用，需替换为 Native 组件库
  • Supabase Auth 需适配 RN 的 PKCE 流程（@supabase/supabase-js 支持 React Native）
  • YouTube 字幕抓取在后端进行（不影响），但视频播放需使用 react-native-youtube-iframe 或 WebView
  • Stripe 支付需使用 react-native-stripe-sdk
  • AI 流式响应（如有）需适配 React Native 的网络层

预估工作量：2-3 个月（1 名全职开发者）

3.3 Capacitor（混合应用）

将现有 Next.js 应用导出为静态站点，用 Capacitor 包裹为原生 App。 Capacitor 提供 JavaScript → Native API 的桥接层。

优势：

  • UI 层 80-90% 复用（直接使用现有 React 组件）
  • 一条命令即可生成 iOS/Android 项目
  • 可通过插件访问原生功能（相机、文件系统等）
  • Ionic Portals 支持嵌入 React Web 视图

挑战：

  • Next.js SSR 特性无法使用 → 需改用 SSG 或 SPA 模式导出
  • API Routes 不能在客户端运行 → 需部署为独立后端
  • WebView 中视频播放体验不如原生
  • Cookie-based Auth 在 WebView 中可能有问题 → 需改用 token-based
  • 性能瓶颈：所有 UI 在 WebView 中渲染，大列表（长字幕）可能卡顿

预估工作量：3-5 周（1 名全职开发者）

Capacitor 关键风险

Next.js App Router 重度依赖服务端渲染（RSC、Server Actions）。转为 SPA 模式意味着需要重构数据获取方式，所有 cookies()、headers() 等 API 不可用。Auth 流程需要从 PKCE Cookie 方案切换为 token-based。

3.4 Flutter / 原生开发

完全不推荐。需要从零开发 iOS + Android 两套代码（或 Flutter 一套），无法复用任何现有代码。 对于当前项目规模，ROI 极低。

4 本项目特有的移动端挑战

挑战影响缓解措施
YouTube 视频播放 原生 YouTube 播放器在 App 内受限（iframe 策略） 使用 react-native-youtube-iframe 或 Capacitor 的 YoutubePlayer 插件
Supabase Auth (PKCE) 当前依赖服务端 Cookie 管理会话 React Native 的 Supabase SDK 支持原生 PKCE；Capacitor 需改用 token 方案
AI 长时间响应 移动端后台限制（iOS 30s 后台时间） AI 调用已在服务端执行，移动端仅轮询结果，不受影响
长字幕列表渲染 WebView 中大列表滚动性能差 虚拟滚动（@tanstack/virtual）、分段加载、React Native FlatList
离线使用 视频分析需要 AI 调用，无法离线 缓存已分析结果到本地存储，离线可查看历史内容
推送通知 Web 版不支持；移动端可支持 React Native / Capacitor 推送插件 + Supabase Edge Function 触发器

5 推荐方案

推荐：PWA 先行 + React Native (Expo) 作为长期目标

分两步走，先低成本覆盖移动端场景，再根据用户反馈决定是否投入原生开发。

第一阶段：PWA（立即实施，1-2 天）

  • 添加 manifest.json 和 Service Worker
  • 配置启动画面、桌面图标、主题色
  • 实现关键数据离线缓存（已分析视频的元数据、字幕、摘要）
  • 收益：用户在手机浏览器打开即可获得全屏体验，可"添加到主屏幕"

第二阶段：React Native + Expo（根据数据决策，2-3 个月）

  • 当移动端用户占比 > 30% 或者 PWA 无法满足需求时启动
  • 优先实施：视频工作区核心功能（播放 + 字幕 + 要点 + 摘要）
  • 后续迭代：Chat、笔记、单词本、句子本
  • 管理后台保留 Web 版本，不纳入 App
